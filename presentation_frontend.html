Архитектура

Структура проекта

Понятные слои: API-клиент → типы → компоненты → страницы.

frontend/src/ ├── api/ # клиент + методы эндпоинтов │ ├── client.ts # axios, токен, 401-refresh │ └── index.ts # authApi, carApi, rentalApi… ├── types/api.ts # модели API (строгие) ├── pages/ # 15 страниц по разделам ├── components/ # ui.tsx, CarCard, Calendar… ├── layouts/ # шапка, сайдбар, admin ├── features/auth/ # AuthContext + RequireAuth └── index.css # вся тема в одном файле
Данные — только через Query
Ни одного ручного fetch: кэш, отмена, повтор при ошибке, refetchOnWindowFocus.
Авторизация в контексте
AuthContext хранит user и токен; RequireAuth закрывает приватные маршруты по ролям.
Валидация форм = как в API
Одни и те же правила (бренд, год, цена) на фронте и бекенде — меньше ошибок.
Интеграция

API-клиент

Один axios-инстанс: подстановка токена, авто-refresh при 401, единая обработка ошибок.

// api/index.ts — методы export const carApi = { list: (p) => client.get<Paginated<Car>>('/car/', { params: p }), detail:(id) => client.get<Car>(`/car/${id}/`), create:(d) => client.post<Car>('/car/', d), bulkUploadImages: (carId, files) => { // FormData + несколько файлов сразу files.forEach(f => form.append('images', f)) return client.post('/car/image/bulk-upload/', form) }, }
Interceptor: Bearer + 401
Токен подставляется автоматически; при 401 — обновление refresh-токеном и повтор запроса.
Типы из API
Car, Rental, Paginated<T> — строгая типизация всех ответов.
Ошибки в тосты
apiErrorText(err) достаёт читаемое сообщение из DRF-ответа → toast.error.

Менеджер фото машины

Основное фото
