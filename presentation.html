Обзор

Что умеет бэкенд

Маркетплейс: владельцы сдают машины, арендаторы берут. Полный цикл «из коробки» — от регистрации до отчётов админа.

01
Каталог и поиск
Фильтры (бренд, цена, топливо), поиск по тексту, пагинация, фото и массовая загрузка.
02
Бронирование
Автопроверка занятости дат, календарь по дням, поиск свободных машин на даты.
03
Цикл аренды
Заявка → подтверждение → старт → завершение. Цена = цена_за_день × дней.
04
Отзывы и рейтинги
Только участники завершённой аренды. Отзывы на машину и на арендатора.
05
Чат и уведомления
Чат создаётся при брони, уведомления по email/SMS, отметки прочитанного.
06
Дашборд админа
Пользователи, жалобы, аналитика платформы и журнал аудита — всё через API во фронте.

Права

Роли

Каждый видит и может только своё. Права проверяются на уровне views и permissions.

R
Арендатор · renter
берёт машины · создаёт аренды · отзывы на машину · чат · жалобы · избранное
O
Владелец · owner
добавляет машины · блокирует даты · подтверждает/отклоняет аренды · видит свой доход
A
Админ · staff
дашборд: пользователи, жалобы, аналитика, аудит. Не лезет в машины и аренды.
is_staff не выдаётся через API — защита от эскалации прав отзыв меняет только автор или админ суперпользователя меняет только суперпользователь

Реальные запросы к API

Сценарий снят с работающего бэкенда: регистрация → JWT → машина → аренда → отзыв. JWT-токены сокращены, вложенные объекты — фрагменты.

POST/register/
Тело запроса
{ "username": "ivan", "email": "ivan@mail.ru", "password": "secret123" }
Ответ 201 Created
{ "username": "ivan", "email": "ivan@mail.ru", "phone_number": null, "is_owner": false }
POST/login/
Тело запроса
{ "username": "ivan", "password": "secret123" }
Ответ 200 OK
{ "user": { "id": 1, "username": "ivan", "email": "ivan@mail.ru", "is_owner": false, "is_renter": true, "is_staff": false }, "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }
Дальше токен идёт в заголовок каждого запроса
Authorization: Bearer <access>
POST/car/владелец dmitry
Тело запроса
{ "brand": "Toyota", "model_name": "Camry", "year": 2021, "fuel_type": "petrol", "transmission": "auto", "mileage": 45000, "price_per_day": "50.00", "location": "Москва", "deposit": "100.00" }
Ответ 201 Created
{ "id": 1, "brand": "Toyota", "model_name": "Camry", "year": 2021, "price_per_day": "50.00", "location": "Москва", "owner": { "id": 2, "username": "dmitry", "is_owner": true, ... }, "is_available": true, "average_rating": null }
POST/rental/арендатор ivan
Тело запроса
{ "car_id": 1, "start_date": "2026-09-02", "end_date": "2026-09-06" }
Ответ 201 Created — цена посчитана сервером
{ "id": 1, "car": { "id": 1, "brand": "Toyota", "model_name": "Camry", "price_per_day": "50.00" }, "start_date": "2026-09-02", "end_date": "2026-09-06", "total_price": "250.00", // 50 × 5 дней "status": "pending" }

Надёжность

Защита от двойного бронирования

Два человека бронируют одну машину одновременно — система не даёт им перекрыть даты.

A
Пользователь A
1–7 августа
B
Пользователь B
8 августа — ждёт
Второй запрос блокируется и получает 400 «Автомобиль уже забронирован»
Машина
блокировка строки через select_for_update()
ATOMIC_REQUESTS — запрос в одной транзакции PostgreSQL/MySQL — работает; SQLite — no-op
Администрирование

Дашборд админа и аудит

Принцип маркетплейса: доходы пользователей для админа анонимны — он видит активность, но не суммы.

AU
Аудит действий
AuditLog фиксирует: регистрации, блокировки, верификацию, роли, статусы жалоб, ответы админа.
PR
Приватность финансов
В операциях и аналитике админа нет сумм. Доход видит только владелец в своём /analytics/.
RO
Журнал read-only
В админке Django журнал только для просмотра — записи нельзя подделать или удалить.
SE
Безопасность
CORS ограничен Vite-портом, throttle 100/1000 в час, пароли хэшируются, is_staff read-only.
DA
Управление
Пользователи, жалобы (статус + ответ), KPI платформы, топ машин по сдаваемости.
RN
Уведомления
Email/SMS: новая заявка, подтверждение/отказ, сообщение в чате, коды верификации.
